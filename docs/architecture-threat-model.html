Threat model
Every threat below is blocked in code and checked by a named test in this repo.
#ThreatHow it is blockedEnforced inChecked by
T1Insurer learns the diagnosisMedical data stays on the device or encrypted; only commitments and the 8 public signals go on-chainclaim.circom · designrecords: someone without access learns nothing
T2Unlisted hospital files a claimHospital key + payout wallet proven inside the approved Merkle root; EdDSA signature over the claimclaim.circomcircuit: hospital not on the list; signed by another hospital
T3Claim outside the policystart ≤ claim date < expiry, procedure in the covered set, amount ≤ limit, all range-checkedclaim.circomcircuit: expired, not covered, over limit, overflow
T4Same claim paid twiceNullifier from policy + claim ID + salt; marked used before any paymentInsureTrust.solcontract: same claim submitted twice
T5Copied proof redirects the payoutThe payout wallet is a public input bound inside the proof (front-running fails)claim.circom · InsureTrust.solcircuit + contract: payout wallet swapped
T6Proof replayed elsewhereChain ID and contract address are bound in the proof and checked on-chainInsureTrust.solcontract: proof made for a different contract
T7Stranger submits the claimOnly the registered policy holder (the patient) can submitInsureTrust.solcontract: only the policyholder can submit
T8Stranger reads a recordAES-256-GCM ciphertext; record key wrapped per reader with X25519; tampered files rejectedWeb Crypto · HealthRecords.solrecords: a shared key opens only for that person
T9Unapproved hospital writes recordsThe patient approves record writers on-chain and can take approval backHealthRecords.solrecords: only hospitals the patient allowed
T10Guessing values from a commitmentEvery commitment includes a random secret salt, so small value sets can't be brute-forcedclaim.circomcircuit: policy terms must match the fingerprint
Known limitsRevoking can't erase a copy a doctor already saw · a unique price could hint at the procedure · one insurer admin key (multisig in production) · Groth16 phase-2 setup has one contribution (needs a multi-party ceremony) · addresses and timings on-chain are public · the hosted demo keeps encrypted files in the browser, not public IPFS
